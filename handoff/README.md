### Quatre blocages d'embarquement corrigés

Un audit exécuté de bout en bout a mesuré un **time to first invoice de 25 à 40
minutes**, dont moins d'une seconde de calcul. Le moteur est excellent ; c'était
la porte d'entrée qui écartait les arrivants.

1. **`gofact mcp` ne chargeait jamais le `.env`** (`runMCP` n'appelait pas
   `dotenv.LoadDefault`). Toute la configuration par fichier était morte sur le
   parcours phare, dont `GOFACT_CHROME` — seul recours proposé par les messages
   d'erreur en mode MCP, puisqu'il n'y a pas de ligne de commande où passer
   `-chrome`. Corrigé, vérifié avec témoin.
2. **`install.sh` posait le binaire dans `${XDG_DATA_HOME:-$HOME/.local}/bin`**,
   soit `~/.local/share/bin` dès que la variable existe. Corrigé en
   `${XDG_BIN_HOME:-$HOME/.local/bin}`, avec avertissement si le répertoire n'est
   pas dans le `PATH`, et vérification de la somme de contrôle.
3. **Organisation sans IBAN = impasse.** `BR-50` à la dernière étape,
   `init_organization` refuse d'écraser, aucun outil pour corriger. Ajout de
   `update_organization` (+ `workspace.UpdateIdentity`, + test) et le message de
   non-conformité nomme désormais l'outil qui corrige.
4. **`go test ./...` rouge sur toute machine sans navigateur.** Les tests de bout
   en bout se dispensent au lieu d'échouer. Vérifié en CI qu'ils tournent bien
   quand un navigateur est là (5,05 s sur ubuntu, 7,24 s sur Windows — un saut
   prend 0,05 s).

Plus : `gofact` sans argument affiche un écran d'aide qui nomme ses commandes ;
les trois versions divergentes (binaire 0.1.0, plugin 1.1.0, skill 3.0.0) sont
alignées sur 1.0.0 ; `scripts/mcp-launcher.sh` est supprimé.

### Le plugin

Il déclarait `${CLAUDE_PLUGIN_ROOT}/scripts/mcp-launcher.sh`, un script qui
compilait le binaire au premier usage — donc exigeait Go chez l'utilisateur, et
ne tournait pas sous Windows. Il déclare maintenant directement la commande
`gofact`. Deux faits vérifiés en documentation qui contraignent ce choix :

- le délai de démarrage d'un serveur MCP est de **10 secondes par défaut**
  (`MCP_TIMEOUT`), donc rien qui télécharge ou compile ne tient ;
- le format de plugin **n'offre aucune configuration conditionnelle par
  plateforme**, donc un lanceur `.sh` exclut Windows.

Conséquence assumée : le plugin apporte la découverte et le skill, **pas** une
installation en zéro étape — le binaire reste requis.

### Release déclenchable sans poste

`.github/workflows/release.yml` accepte désormais `workflow_dispatch` avec le tag
en entrée : le job pose le tag lui-même sur le commit courant. Le push utilise le
`GITHUB_TOKEN` par défaut, dont les événements ne déclenchent aucun workflow — la
release ne peut donc pas partir deux fois.

## 5. Ce que l'audit concurrentiel a changé

Deux découvertes qui ont obligé à corriger le positionnement :

- **`angelodlfrtr/go-invoice-generator/facturx`** (146 étoiles, Apache-2.0)
  assemble déjà du Factur-X PDF/A-3B en Go pur, cinq profils, validé mustang-cli
  et veraPDF. « PDF/A-3 sans Java » **n'est pas un différenciateur** — le
  revendiquer expose à une correction publique méritée. La différence
  défendable : produit contre bibliothèque. Un indépendant n'écrira pas de Go
  pour facturer.
- **`causa-prima-ai/scribo`** fait de l'e-facturation « AI-native » EN 16931 avec
  MCP, en production en Allemagne et aux États-Unis, **France annoncée**. Le
  pilier conversationnel n'est pas vierge. Il reste défendable sur ce qu'un SaaS
  propriétaire ne peut pas offrir — pas de compte, exécution locale — mais la
  fenêtre se referme, ce qui plaide pour accélérer les canaux MCP.

Ce qui reste réellement propre à gofact : l'embarquement verbatim préservant
BT-34/BT-49, les règles EN 16931 appliquées *avant* production, la numérotation
légale hors modèle de langage, et local-first + AGPL + français.

Limites à ne jamais masquer : TVA mono-taux, une seule plateforme agréée
(SuperPDP), devises ≠ EUR incomplètes.
